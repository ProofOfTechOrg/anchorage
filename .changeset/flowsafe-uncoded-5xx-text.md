Breaking: a `5xx` that carries no reason code no longer carries the message of the fault behind it. `doSummary()` and the readers inside `createDoRunTopology()` and `createAgentThreadTopology()` keep the status of such an answer from a run or thread object, replace its message with `internal error`, and log the original as a `route-internal-error` line. The signal ingestion router does the same for a thread object's answer it forwards, the stream router for the run or hub object's answer to a WebSocket upgrade it forwards, and `createRunRouter()` for a `DeploymentIdentityError` thrown in process, which keeps its `503`. Before this change a host that reaches its runs through Durable Objects answered an unclassified run-object failure, such as a D1 error, with its message at `500` on `/api/runs`, and a deployment-identity failure, whose message names deployment tags and bindings, at `503`. The agent and stream routers now pass every `RunRouteError` through with its status, message and reason: a `503` without a reason code, such as `persisted start is not readable` or a permission resolver failure, answers `503` instead of `500`, and the stream router answers any other failure with `500` and `internal error` instead of the failure's message. The stream router now forwards a `RunRouteError`'s reason as written, where it forwarded only a reason that carries a code. A `RunRouteError` or `DoStatusError` whose status is outside `400`-`599` answers `500` from the run, agent, stream, schedule, objective, signal and signal-subscription routers and from the composed Worker's fence and inventory admin routes, which used to throw or answer with that status. A non-ok answer from a run object whose body is not JSON keeps its status in `doSummary()`, where it used to become a `500`.
