Breaking: the approval router answers an unexpected failure with `500` and `{ "error": "internal error" }`, logging the original, instead of the failure's message, and every approval response carries `cache-control: no-store`. In a batch decide, a record the execution fence refuses reports `code` `unavailable` with the fence's `reason` (`EXECUTION_FENCED` or `EXECUTION_FENCE_UNREADABLE`), as the single-record route answers `503`, instead of `error`, and an unexpected per-record failure reports `error` with the message `internal error` instead of the failure's message. `BatchDecideItem['code']` gains `unavailable`, and the item gains an optional `reason`. `DecideResult.resume.error` carries `internal error` for a failed resume that has neither a reason code nor a 4xx status, such as a storage failure or a `DeploymentIdentityError` thrown in process, instead of the failure's message. The original is logged: for an answer read from a run or thread object, on the reader's `route-internal-error` line, and the `approval.resume` audit event records `internal error` where it recorded the failure's message; for a failure in process, on the `approvals.resume` line and in the `approval.resume` audit event. A refusal `RunnerRuntime` throws in process through `resumeViaRuntime`, such as `UnknownRunError`, carries no status, so it reports `internal error` too.
