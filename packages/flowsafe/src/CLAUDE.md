Lives here, not in do-runner/memory-id.ts, because the guard's contract IS its `RunRouteError` status and `TenantContext` lives in approval-api, which already imports do-runner. Every memory-touching route MUST call both — the rule Track A/C's routes adopt; no such route ships in Track 0 — docs/agent-memory-tenancy.md item 5). PLUS `thread-topology.ts` — `createThreadTopology(namespace)`, the SANCTIONED way to reach a per-thread DO and the MINTER for the `THREAD_TENANT_HEADER` `ThreadDurableObject` verifies: `send`/`forward` ownership-404 the threadId (before the DO is addressed — no wake, no oracle) and stamp the header from the RESOLVED `TenantContext`, `forward` OVERWRITING (never appending) whatever the client's own request carried. Mint and verify ship together for stream-ticket's reason: the house DO-forwarding idiom (`hub-topology`'s `stub.fetch(request)`) forwards client headers verbatim, which is safe for the hub (it trusts the request for nothing) and a bypass for a thread route (the client would write the header the DO authenticates on).
