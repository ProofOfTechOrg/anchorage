## Subdirectories

| Directory | What | When to read |
| --------- | ---- | ------------ |
| `do-runner/` | Cloudflare Durable Object workflow runner: `init()` import-swap, `RunnerRuntime` (with the `requestContextForRun` grant-minting seam + widened `status()`), `DurableObjectRunner`, D1 storage | Implementing or modifying durable execution, suspend/resume, or DO HTTP routing |
| `approval-api/` | Phase 3 approval queue: CAS store (D1 + in-memory), role-authorized service (SLA/escalation/audit), REST router, grant derivation | Implementing or modifying the approval queue or grant minting |
| `approval-ui/` | React approval dashboard (queue/detail/metrics) + DOM-free API client; compiles in its own tsc pass | Implementing or modifying the dashboard |
| `host-kit/` | Host-agnostic glue every host shares. `./host-kit` (barrel, deliberately **breakwater-free**): the identity seam (`TokenVerifier` — `staticTokenVerifier` + HS256 `hmacVerifier`/`mintHmacToken` in `verifier.ts`; `parseActorTokens` requires an INV-3 `tenantId` per entry and rejects the reserved identity `system`; `bearerActorAuthenticator(verifier)`), `createRunRouter({ resolve })` (401 → INV-3 → coarse `RUN_START_ROLES` → per-workflow `allowedRoles` on EVERY mutating route, start via the body's workflowId and resume via the path's — reads stay coarse; rejects client runIds and mints `${tenantId}_${uuid}`; 404s other tenants' runs on status/resume — no existence oracle, and the ownership 404 precedes the role 403), the tenants allocation registry (`tenant-registry.ts`: `provisionTenant` insert-or-fail + `RESERVED_FOR_ALLOCATION` at provisioning/routing vs `RESERVED_TENANT_IDS` at authentication, re-refused by `createTenantResolver` for custom verifiers that bypass `toApprovalActor` — two lists by design; re-conflating them would 401 a single-tenant host named `api` or `default`), the subdomain↔tenant cross-check (`subdomain-check.ts`; `subdomainTenantOf` and the bridge's `requestedConnectors` stay module-internal), `RunRouteError` + `doSummary`, `assertWorkflowsRegistered`, the approval bridge (`queueApprovalForSuspension` files one record PER suspended path — parallel gates all reach the queue — returning `ApprovalRecord[]`; `resumeRunWithRequeue` emits an `approval.requeue`/`error` audit event when post-resume re-filing throws; `reconcileApprovalsForSummary` + the `reconcileApprovalsOnStatus` factory back `createRunRouter`'s optional `reconcileApprovals` hook — on a suspended `status()` read, any suspended step whose CURRENT `(suspendedAt, resumeCount)` fingerprint has no record of any status gets a fresh system-requested approval, after first SUPERSEDING every stale OPEN record for that step (`ApprovalService.supersedeStale` — a CAS transition straight to `rejected`, system-attributed, audited as `approval.supersede`, never through `decide()` so a stale request dies without touching the run; a concurrent real decision winning the CAS makes reconcile back off that step for the round instead of clobbering it), the D4 self-healing loop), the shared host glue (`do-run-topology.ts` — `createDoRunTopology(namespace)`, the DO-stub start/status/resume + `resumeRecord` thunks; `host-approval-service.ts` — `buildHostApprovalService`, `hostAuditSink`, `maintenanceActor`, `approvalStoreFactoryFor` isolate memo, `runSlaSweepMaintenance`, `runApprovalRetentionPurge` (mirrors `runSlaSweepMaintenance`'s shape — de-duplicates the approval-retention purge block the two hosts previously hand-copied; unlike the sweep it logs no own summary line, since callers fold its count into their own combined maintenance log), `reconcileApprovalsOnStatusDetached` (the waitUntil-detaching reconcile wrapper ExecutionContext-capable hosts wire instead of the awaited host-agnostic default — owns the detach + `reconcile-error` logging once); `env-vars.ts` — `numberVar` with `allowZero` + fail-closed `boolVar`), `WorkflowMeta`, and `flowsafe-worker.ts` — `createFlowsafeWorker(config)`, the composed production Worker both hosts consume as thin shells: the /healthz → preRoutes → approvals → runs → 404 fetch pipeline over ONE resolver, the two-cron `scheduled()` dispatch with per-duty failure isolation, and the audit-export `queue()` consumer; seams `buildVerifier`, `preRoutes` (receives `{resolve, topology}`), `wrapResolve`, `wrapStart`/`wrapResume`, `notify` (ApprovalNotificationSink factory), `extraPurgeDuties` (fields fold into the ONE combined maintenance log line). PLUS the Part B live-streaming surface: `stream-ticket.ts` (`mintStreamTicket`/`verifyStreamTicket` — a short-lived HMAC addressing ticket bound to tenant+channel+runId?+actor+exp over verifier.ts's HS256 primitives; fail-closed verify, constant-time compare, addressing-only NEVER a grant), `hub-topology.ts` (structural `HubNamespaceLike`/`HubStubLike` + `createHubTopology` — publish an event to `idFromName(record.tenantId)` / forward a verified WS upgrade), and `stream-router.ts` (`createStreamRouter` — `POST /api/stream/ticket` with the run-channel ownership 404, plus the ticket-verified `GET /api/stream/hub` and `GET /api/stream/run/:wf/:runId` upgrade routes, all under `/api/stream/*`; the Worker is the SOLE ticket authority, DOs re-bind by `idFromName`). `createFlowsafeWorker` mounts the stream stage between preRoutes and approvals ONLY when `env.HUB` + `env.STREAM_TICKET_SECRET` are both present (opt-in with poll fallback, DL-019), threading the fetch-scope hub sink via `ctx.waitUntil` and the cron sink via the sweep's collected `pendingSends` keepalive (DL-020). `./host-kit/module` (separate subpath): the `WorkflowModule` authoring contract | Changing the shared run routes, identity seam, tenant registry, host service assembly, the suspension→approval bridge, the stream router/ticket/hub seam, or the composed Worker |
| `audit-export/` | Cloudflare Queues audit export (Phase 4): `queueAuditSink` producer adapter, `createAuditQueueConsumer` batch→SIEM HTTP export (NDJSON, transform envelope, ack-on-2xx/retry-otherwise), and `createAuditQueueHandler` — the whole Worker `queue()` handler (endpoint-unset ⇒ config-error + retry, fail closed) hosts mount verbatim | Implementing or modifying audit export to SIEMs |
| `artifacts/` | R2 workflow artifact storage (Phase 4): `R2ArtifactStore` over a structural `ArtifactBucket` seam (+ `InMemoryArtifactBucket`), keys `[prefix/]workflowId/runId/name` validated by the shared `PATH_SAFE_ID_PATTERN`, `deleteRun` pairs with retention purge | Implementing or modifying artifact storage |
